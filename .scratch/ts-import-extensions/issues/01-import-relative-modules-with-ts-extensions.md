# 01: Import relative modules with `.ts` extensions

**Status:** ready-for-agent

**Blocked by:** None

> *This was generated by AI during triage.*

## Agent Brief

**Category:** enhancement
**Summary:** Every relative import in server-side TypeScript names the `.ts`
file it imports, and `tsc` rewrites it to `.js` on emit
(`kanku-typescript-style` R3).

**Current behavior:**
`apps/backend`, `packages/data` and `packages/api-contracts` write relative
imports as `./x.js`. On 2026-10-31 that was 151 imports in 52 files, counting
`from` and dynamic `import()`. No tsconfig sets
`rewriteRelativeImportExtensions`. The data and contracts packages export their
source through a `types` condition and their compiled `dist/` through
`default`, so the Backend and the Admin UI type-check package source directly.

**Desired behavior:**
One import convention, changed in one PR so no package mixes `.js` and `.ts`
imports:

- The tsconfigs of `apps/backend`, `packages/data` and `packages/api-contracts`
  set `"rewriteRelativeImportExtensions": true`.
- Every relative `from "./x.js"` and `import("./x.js")` in those packages names
  `.ts` instead, test files and `drizzle.config.ts` included. Package imports
  (`@ez-dk-citizen/data`, `hono/body-limit`) stay as they are.
- The Admin UI's tsconfig sets `"allowImportingTsExtensions": true`. It already
  sets `noEmit`, which the flag requires. The Admin UI type-checks the
  contracts package's source, so without the flag the first `.ts` import
  between contracts files would fail its typecheck. Nothing fails yet: the
  contracts package's only relative import is in its test file, which the
  Admin UI doesn't load.
- The emitted `dist/` keeps `.js` imports, so the `exports` maps, `start`,
  `test:compiled` and the Docker images need no change.

Triage tried exactly this change on a throwaway worktree off `main` on
2026-10-31, with TypeScript 7.0.2. `typecheck`, `lint`, `build` and `test`
passed, `db:generate` found no schema changes, `dist/` held no `.ts` imports,
and Node loaded each package's compiled entry. `dist/` holds fewer relative
imports than the source (119 against 151) because `verbatimModuleSyntax` drops
`import type` on emit. That gap is expected.

**Key interfaces:**

- `compilerOptions.rewriteRelativeImportExtensions` in the three server-side
  tsconfigs.
- `compilerOptions.allowImportingTsExtensions` in the Admin UI tsconfig.
- Each package's `exports` map (`types` to source `.ts`, `default` to
  `dist/*.js`) stays unchanged.

**Acceptance criteria:**

- [ ] No relative import in `apps/backend`, `packages/data` or
      `packages/api-contracts` ends in `.js`.
- [ ] The emitted `dist/` files, `.d.ts` included, import `.js`, never `.ts`.
- [ ] `pnpm db:generate` still loads the Drizzle schema and generates no
      migration.
- [ ] `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`,
      `pnpm test:integration`, and `pnpm test:e2e` pass.

**Out of scope:**

- Running TypeScript through Node's type stripping instead of `tsx`. This
  ticket makes that possible, but it is a separate convention.
- `erasableSyntaxOnly`, Vitest, and the other tooling differences from the
  skill.
- The Admin UI's own imports, which stay extensionless as Vite resolves them.
