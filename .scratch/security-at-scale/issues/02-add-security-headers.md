# 02: Add security headers to every Backend response

**Status:** ready-for-agent

> *This was generated by AI during triage.*

## Agent Brief

**Category:** enhancement
**Summary:** Every Backend response carries Hono's default security headers
(`kanku-typescript-style` R19).

**Current behavior:**
Backend responses carry no security headers. Checked on 2026-10-30 through
`app.request` against `createBackendApp`: a 200 from the health route, a 500
Problem Details, a 401 from the Admin API and a 404 for an unknown path came
back with only `content-type`, `x-request-id` and, on the 401,
`www-authenticate`. This repo carries no Caddy site snippet that adds them in
front of the Backend either.

**Desired behavior:**
Every response from the Backend, on both the Admin API and the Mobile API,
carries the headers Hono's `secureHeaders` middleware sets with its defaults,
and no `X-Powered-By`. That covers success responses, every Problem Details
error response (validation, refusals, 401, body too large, 500) and 404s for
unknown paths. Apply the middleware once, where the app is built, so it wraps
every route and no route module has to remember it.

Use the defaults unchanged, including
`Strict-Transport-Security: max-age=15552000; includeSubDomains` (the
maintainer's decision during triage). Hono sets no Content-Security-Policy by
default; leave it unset.

Triage settled that the defaults are safe for today's clients:

- Media Asset uploads go from the browser straight to S3 through presigned
  URLs, so they never pass through the Backend.
- The Admin UI is a separate app that calls the Backend with CORS requests.
  `Cross-Origin-Resource-Policy: same-origin` applies only to no-cors requests,
  so it doesn't affect them.
- The Backend serves only JSON, never HTML or media bytes.

**Key interfaces:**

- `createBackendApp(checkReadiness, options)`: builds the one Hono app that
  serves both APIs, so the middleware belongs there.
- Route tests build the app through `createBackendApp` and assert with
  `app.request(...)` (R16).

**Acceptance criteria:**

- [ ] A success response (the health route) carries
      `X-Content-Type-Options: nosniff`,
      `Strict-Transport-Security: max-age=15552000; includeSubDomains`,
      `Referrer-Policy: no-referrer` and `X-Frame-Options: SAMEORIGIN`.
- [ ] A Problem Details error response (a 401 from the Admin API without a
      token) carries the same headers.
- [ ] A 404 for an unknown path carries the same headers.
- [ ] A Mobile API response carries the same headers.
- [ ] The existing tests, `typecheck` and Biome pass.

**Out of scope:**

- Content-Security-Policy, Permissions-Policy and any other header Hono doesn't
  set by default.
- Rate limiting; the Mobile API's is deferred in 01.
- The Caddy configuration on the server.
- Changing the existing custom middleware (request ID, logging, CORS, admin
  auth).
